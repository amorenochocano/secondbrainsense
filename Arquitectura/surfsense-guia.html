PASO 01 · ~5 min
Instalación Docker
Dos modos de instalación. Para empezar rápido: imagen all-in-one. Para producción: docker-compose.
Modo rápido — Un solo comando
# Linux / macOS
docker run -d \
  -p 3000:3000 \
  -p 8000:8000 \
  -p 5133:5133 \
  -v surfsense-data:/data \
  --name surfsense \
  --restart unless-stopped \
  ghcr.io/modsetter/surfsense:latest

# Con embeddings OpenAI (opcional, mejor calidad)
docker run -d \
  -p 3000:3000 -p 8000:8000 -p 5133:5133 \
  -v surfsense-data:/data \
  -e EMBEDDING_MODEL=openai://text-embedding-ada-002 \
  -e OPENAI_API_KEY=sk-... \
  --name surfsense \
  --restart unless-stopped \
  ghcr.io/modsetter/surfsense:latest
Modo producción — Docker Compose (team / empresa)
git clone https://github.com/MODSetter/SurfSense
cd SurfSense
cp .env.example .env
# Edita .env con tus valores (ver paso 02)
docker-compose up -d --build
Acceso tras instalación
  • UI principal → http://localhost:3000
  • API backend → http://localhost:8000
  • API docs (Swagger) → http://localhost:8000/docs
  • pgAdmin (gestión DB) → http://localhost:5050
Comandos útiles de gestión
docker logs -f surfsense        # Ver logs en tiempo real
docker stop surfsense           # Parar
docker start surfsense          # Arrancar
docker pull ghcr.io/modsetter/surfsense:latest
docker rm surfsense && docker run ...  # Actualizar

PASO 02 · ~15 min
Configuración .env
Las variables críticas que debes configurar antes de arrancar. Sin ellas, funciona en modo degradado.
.env — Variables esenciales
# ── FRONTEND ──────────────────────────────
FRONTEND_PORT=3000
NEXT_PUBLIC_API_URL=http://localhost:8000

# ── BACKEND ───────────────────────────────
BACKEND_PORT=8000
SECRET_KEY=cambia-esto-por-algo-aleatorio-seguro

# ── BASE DE DATOS ─────────────────────────
POSTGRES_USER=postgres
POSTGRES_PASSWORD=pon-una-password-segura
POSTGRES_DB=surfsense
POSTGRES_PORT=5432

# ── LLM PRINCIPAL (elige uno) ─────────────
# Opción A: Claude (recomendado)
ANTHROPIC_API_KEY=sk-ant-...

# Opción B: OpenAI
# OPENAI_API_KEY=sk-...

# Opción C: Local con Ollama
# OLLAMA_BASE_URL=http://localhost:11434

# ── EMBEDDINGS ────────────────────────────
EMBEDDING_MODEL=local://nomic-ai/nomic-embed-text-v1.5
# EMBEDDING_MODEL=openai://text-embedding-3-small

# ── BÚSQUEDA WEB (opcional) ───────────────
TAVILY_API_KEY=tvly-...
# LINKUP_API_KEY=...

# ── PROCESADO DE FICHEROS ─────────────────
UNSTRUCTURED_API_KEY=...   # platform.unstructured.io
⚠️ Decisión crítica: LLM local vs API
⚠️ Para segundo cerebro personal con datos sensibles → Ollama local (llama3, mistral). Para calidad máxima en empresa → Claude API o GPT-4o. Los embeddings locales (nomic-embed) son suficientemente buenos para empezar sin coste.

PASO 03 · ~5 min
Crear Search Spaces
El Search Space es la unidad fundamental de SurfSense — un workspace aislado con sus propios docs, conectores, chats y miembros. Piénsalo como un 'proyecto' o 'contexto' de conocimiento.
Estructura recomendada
🧠 'Mi cerebro' — Notas personales, libros, artículos, PDFs propios
💼 'Trabajo' — Docs del equipo, wikis, decisiones técnicas
🚀 'Proyecto Alpha' — Knowledge base específica de un proyecto
📚 'Investigación' — Papers, referencias, recursos de aprendizaje
Cómo crear un Search Space
1Ir a http://localhost:3000 → Login
2Dashboard → botón 'New Search Space'
3Nombre + descripción + configurar LLM para este espacio
4Opcionalmente: invitar miembros con su rol (Admin / Editor / Viewer)
5Listo — ya puedes añadir conectores y documentos
Tip: Obsidian → SurfSense
  • Conecta tu vault de Obsidian usando 'Watch Local Folder'
  • SurfSense detecta cambios automáticamente y re-indexa
  • Tus notas Markdown quedan buscables semánticamente
  • El mejor bridge entre segundo cerebro personal y RAG

Flujo de configuración (ej: GitHub)
1Settings → Connectors → 'Add Connector'
2Seleccionar GitHub → introducir Personal Access Token
3Seleccionar repos a indexar (puedes filtrar por org/repo)
4Configurar frecuencia: real-time (webhook) / horaria / diaria
5Click 'Index Now' para primera ingesta inmediata
6Verificar en 'Documents' que los ficheros aparecen indexados
Credenciales que necesitarás
# GitHub → Personal Access Token (PAT)
# github.com → Settings → Developer settings → PAT
# Permisos: repo (read), read:org

# Notion → Integration Token
# notion.com/my-integrations → Create integration

# Slack → OAuth App
# api.slack.com/apps → Create app → OAuth tokens
# Permisos: channels:history, files:read, search:read

# Google Drive → Service Account o OAuth
# console.cloud.google.com → APIs → Drive API → Credentials

# Jira → API Token
# id.atlassian.com → Security → API tokens

PASO 05 · ~10 min
Subir Documentos
Además de los conectores automáticos, puedes subir documentos manualmente. SurfSense soporta 50+ formatos.
Pipeline interno de procesado
Upload / Fetch→ ETL Service→ Markdown→ Chunking→ Embeddings→ PostgreSQL + pgvector
Formatos soportados
  • Documentos: PDF, DOCX, PPTX, XLSX, ODT, RTF
  • Texto: MD, TXT, HTML, CSV, JSON, XML
  • Código: py, js, ts, go, rs, java, cpp, y más
  • Multimedia: imágenes (con OCR), audio (transcripción)
⚠️ PDFs complejos con tablas o columnas
⚠️ Para PDFs con tablas, formularios o layout complejo, configura UNSTRUCTURED_API_KEY en el .env. Sin ello, la extracción de PDFs complejos será deficiente. El plan gratuito de Unstructured.io tiene 1000 páginas/mes.

PASO 06 · Uso diario
Chatear con tu Knowledge Base
Tres modos de interacción: Chat RAG (documentos propios), Researcher (web + docs), y Chat colaborativo en equipo.
Modos de chat disponibles
🧠 Chat RAG — Solo tu knowledge base. Respuestas con citas exactas al doc/chunk fuente.
🔍 Researcher — Combina tu knowledge base + búsqueda web en tiempo real.
👥 Chat compartido — Equipo chatea en tiempo real en el mismo hilo con menciones.
🎙️ Podcast — Genera audio de 3 min desde cualquier conversación o documento.
Tips para mejores resultados
1Sé específico — 'explícame el módulo de auth de proyecto-x' > 'explícame auth'
2Usa Researcher cuando necesites info actual + tu contexto interno
3Revisa siempre las citas — SurfSense muestra el chunk exacto de donde viene cada respuesta
4Si la respuesta es mala, verifica que el documento esté indexado en Documents
5Para código: pregunta por función/clase ('cómo funciona refreshToken()')

PASO 07 · ~10 min setup
Colaboración en Equipo
Para el caso empresa: invitar al equipo, asignar roles y compartir Search Spaces.
Roles disponibles
Admin — Control total: gestión de miembros, conectores, LLM configs, CRUD docs
Editor — Añadir docs y conectores, crear chats, NO gestionar miembros
Viewer — Solo leer y chatear, NO modificar la knowledge base
Flujo de invitación
1Search Space → 'Manage Members' → 'Create Invite'
2Configurar: rol asignado, límite de usos, fecha de expiración
3Copiar link de invitación y enviarlo al teammate
4El teammate se registra y el Search Space queda compartido automáticamente
5Activar 'Make chat shared' para colaboración en tiempo real
Acceso desde otros portátiles (VPN)
  • Averigua tu IP de VPN: ip addr | grep "inet " (Mac/Linux) o ipconfig (Windows)
  • Configura NEXT_PUBLIC_API_URL=http://TU_IP_VPN:8000 en el .env
  • El equipo accede por navegador a http://TU_IP_VPN:3000
  • Sin instalar nada en los portátiles del equipo — solo un navegador
